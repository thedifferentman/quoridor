# 路墙棋游戏

游戏本体位于仓库的 `game/` 目录。本文中的 `backend/`、`frontend/` 和 `data/` 路径均相对于该目录。

## 相对原始仓库的变更（2026-10-19）

原始仓库：[james1BadCreeper/quoridor](https://github.com/james1BadCreeper/quoridor)。以下记录游戏本体及运行配置的变化，不包含工作区 `src/`、`experiment/` 中的模型训练和 MCTS 实验。

**兼容性：旧 AI 的整轮 `actions` 数组协议已不再接受。旧 AI 需要更新输入输出处理和合法性判断，再重新上传；仅能成功编译不代表可以继续对战。**

### 1. 目录与启动

- 游戏整体迁入 `game/`，保留 `backend/`、`frontend/`；上传 AI 数据目录随之成为 `game/data/ais/`。
- 原启动批处理拆为 `launch_backend.bat` 和 `launch_frontend.bat`，分别切换目录、安装依赖并启动后端和前端。
- 前端仍在 `5173`，后端 `8000` 只提供 API，没有新增后端根路径的前端页面。
- 根目录 README 改为工作区说明，忽略规则随目录迁移调整。

### 2. 围死规则与通路检查

- 删除“被围死者获胜”，改为围死任意一方均属非法动作。
- 直墙、L 墙和免费墙都必须保留双方通往各自获胜点的路径；非法墙不消耗资源、不推进回合。
- 通路检查只考虑墙和死点，不把棋子临时占位当成永久阻挡，也不把一次性穿墙当作永久通路。
- 穿墙移动不能进入无法通往己方终点的封闭区域。正常获胜条件为到达自己的获胜点。

### 3. AI 单事件协议

| 项目 | 改动前 | 当前 |
|---|---|---|
| 普通行动 | `actions` 数组 | 单个 `action` 对象 |
| 连续行动 | 一次提交两步 | 每次一步，后端更新真实状态后再次请求 |
| 流沙陷阱 | 流沙与后续行动一起提交 | 先单独放置流沙，再请求后续行动 |
| 其他技能 | 整轮输出的一部分 | 必须与一个动作共同提交 |
| 非法组合 | 可能已执行前面的部分 | 技能和动作整体成功或整体拒绝 |

- 新增 `apply_event()` 统一执行 AI 决策；旧 `actions` 字段直接拒绝，没有自动转换层。
- AI 单步执行结果也改为单个 `action`，成功事件的 `applied` 为 1。
- 原子执行针对 AI 的组合事件；人类玩家仍可通过原有技能面板先使用技能。
- 出题、选边、赛前选牌的阶段协议保留。

### 4. 补齐 AI 输入状态

| 字段 | 含义 |
|---|---|
| `protocol_version` | 当前为 2 |
| `events`、`event_limit`、`remaining_events` | 已用、总计、剩余事件预算 |
| `remaining_moves` | 当前行动序列剩余次数 |
| `skill_used`、`must_move` | 当前序列的技能使用锁、强制移动限制 |
| `phase_buff`、`free_buff` | 双方公开的穿墙、免费墙效果 |
| `l_bonus`、`l_pending` | 双方改造权限和待使用状态 |

上述技能状态大多原本已存在于引擎内部，此次补齐对 AI 的传递。对方手牌仍只提供总数量，不公开技能明细。

### 5. 事件上限、计数与后端回放

- 引擎新增并序列化 `events`、`event_limit`。创建游戏接口支持 `event_limit=1..3000`，默认 800。
- 移动、放墙、单独放置流沙各计一次；普通技能与动作一起提交时不额外计数。赛前准备不计入事件。
- 达到上限判平；最后一个事件到达获胜点时，获胜优先。
- 修复 AI 对战循环重复增加 `plies` 的问题。既有 `max_plies` 参数、`plies` 结果现在统一按事件数解释。
- 批量对战进度、日志和重建保存相同事件预算；重放使用同一个 `apply_event()`，与实战采用相同执行逻辑。

### 6. C++ 公共库和内置 AI

- `ai_common.hpp` 的 `Board` 补充对方余墙、技能锁、强制移动、待用改造状态和事件预算，`parseBoard()` 同步读取。
- `checkDecision()` 改为校验单事件，删除提前模拟第二步的逻辑；`decision()` 第三个参数由动作列表改为单个动作，流沙可省略动作。
- `checkWall()` 强制保留双方通路，删除允许跳过围死检查的参数，并检查强制移动限制。
- `checkMove()` 增加移动后通路检查；输出自检的回退走子也经过合法性检查。
- `sandOk()` 修复为同时禁止双方获胜点放流沙，与后端保持一致。
- 内置贪心、随机 AI 均适配单事件协议、技能锁、强制移动及新的通路规则。
- 修复免费墙使用判断：余墙为零时仍可使用手中的免费墙技能，已有免费墙效果时避免重复打牌。

### 7. Docker、前端和棋谱文件

- 移除 AI 容器的 `--cpus=0.5` 配额；内存、进程数、禁用网络和超时约束保留。Docker 虚拟机本身的资源配置仍生效。
- 前端显示已用事件/事件上限，并区分连续行动的“只能走子”和流沙奖励行动。
- 棋谱导入导出补齐 `event_limit`、事件计数和 `l_pending`。回放中的 `events` 原本是历史事件数组，因此数值计数另外保存为 `event_count`。
- `package-lock.json` 移除部分平台 `libc` 元数据；依赖声明及版本未修改。

### 8. 测试与文档

- 更新原规则和 AI 测试，新增 `backend/tests/test_event_protocol.py`，覆盖单事件、连续行动、技能锁、原子拒绝、事件上限、回放、HTTP 接口和 Docker CPU 配额。
- 新增 `backend/tests/test_cpp_event_protocol.py`：编译两个内置 AI，以真实 JSON 与后端交叉验证，覆盖 9×9、15×15 和准备阶段。
- 更新本文和 `backend/app/ai_cpp_example/README.md` 的规则、字段、输出示例与旧 AI 迁移说明。

本机安装 Docker Desktop、拉取 GCC 编译镜像属于运行环境配置，不属于游戏源码更改。上传文件白名单、编译流程及前后端基本架构未因此改变。

## 规则说明

该游戏为 Quoridor 的改版，规则变动如下：

1. 地图为 $n\times m$ 随机，$n,m\in [9,15]$。双方初始时各有 $v=(n+1)\times (m+1)\times \frac 1 10$ 个墙，向下取整，均为长 $2$ 的直墙（横/竖）。
2. 获胜点不再是对面的一行的全部点，而是由一个玩家选择两个大小为 $m/2$ 的集合 $A,B$，而另一个玩家选择先手、集合 $A$ 为获胜点或者后手、集合 $B$ 为获胜点。进行选择的玩家随机。
3. 地图上会随机较少量的死点（不能进入）和较少量的流沙（如果进入，对方连续行动两次）。
4. 围死任意一方均为非法动作：放置直墙或 L 墙后，双方必须仍有通往各自获胜点的路径；免费墙同样受限。通路检查忽略棋子临时占位，不计一次性穿墙能力；穿墙走子也不能进入不通往己方获胜点的封闭区域。非法动作不落地，人类玩家需重新选择，AI 按既有非法输出规则判负。只有到达获胜点才构成正常获胜，不再有“被围死者获胜”。
5. 技能卡：选定获胜点、知晓地图后，双方各选 $k$ 张技能卡（$k=F(n,m)=\max(2, v//5)$，最小地图取 $2$，可重复，对方不可见，同机对战除外）。技能为：改造（打出后本次行动必须放 L 墙，否则作废）、连续行动（本回合连走两次且都必须是移动）、穿墙（下次走子无视墙）、流沙陷阱（禁获胜点）、免费墙（下次放墙不耗存量）。行动前可打出一张，不占轮次；连续行动序列中最多打出一张；使用时双方均得知。

## 运行方式

Windows 可分别运行 `launch_backend.bat` 和 `launch_frontend.bat`，各自使用一个终端；脚本会自动切换到正确目录并安装依赖。两个服务启动后，访问 **http://127.0.0.1:5173**，`8000` 端口仅提供后端 API。也可按下面的命令手动启动。

后端（从仓库根目录先执行 `cd game`）：

```bash
pip install -r backend/requirements.txt
uvicorn app.main:app --reload --app-dir backend
```

前端（另开终端，从仓库根目录先执行 `cd game/frontend`）：

```bash
npm install   # 国内网络慢可用镜像源
npm run dev   # 访问 http://127.0.0.1:5173（/api 已代理到 8000 端口）
```

测试（在 `game/` 目录执行）：`python -m pytest backend/tests -q`；C++ 示例见 `backend/app/ai_cpp_example/`。也可在仓库根目录执行 `python -m pytest game/backend/tests -q`。

## 实现现状（MVP）

- 后端 `backend/app/engine.py`：随机地图、直墙（长 2，改造现打现放 L 墙）、A/B 获胜列集（相互独立）、死点/流沙（首末行无死点流沙）、流沙罚步、双方通路合法性检查、技能系统（手牌/序列锁/免费墙等 5 种）。
- 接口：开局 `/api/games/new`（支持人类指定 A/B 列集，返回 `skill_k`）、赛前选技能（`/skills/select`、AI 席位 `/skills/ai-select`）、行动前打出手牌（`/skills/play`）、走子/放墙、合法走子查询、AI 出题/选边（`/api/ai/goals`、`/api/ai/side`）、棋谱导出/导入。
- 前端：深色现代 UI；开局向导（随机出题人 → 出题 → 选边 → 双方选技能卡，AI 出题/选边走容器）；技能面板（对战中 AI 手牌对人类隐藏）、L 墙放置与流沙选格；本地双人 / 人机混战 / AI 走到底演示、棋谱导出导入（增量回放格式，旧全快照可导入）、快照回放条。
- AI：C++ 示例（贪心 `ai_example.cpp`、随机 `ai_random.cpp`，共用 `ai_common.hpp` 解析库并捆绑 nlohmann/json，docker 内编译）；外部 AI 上传/编译/对战接口（`POST /api/ai/upload`、`POST /api/ai/match`，沙箱 `--network none` + 超时（默认 5s）+ 内存（默认 256MiB），各 AI 接口均可带 `timeout`/`memory_mb` 覆盖）；默认 AI 列表（`GET /api/ai/list`：内置贪心/随机 + 已上传，前端开局可直选、可上传；`random` 为保留别名，指向容器随机）。

## AI 编写指南

本项目的最大功能是测试编写的 AI 的性能。本节指导你如何编写自己的 AI。

### 1. 总览

- AI 是一个程序：从 stdin 读入一个 json（当前局面），向 stdout 输出一行决策 json。
- 语言不限（示例用 C++，可直接照抄）；源码打成 `.zip` 上传，后端在 docker 沙箱里编译、运行、对战。
- 协议流程：出题与选边 → 赛前选技能卡 → 单事件决策（多次）；出题方另有出题阶段（定 A/B 列集），另一方有选边阶段（先手+A / 后手+B）。
- 测试方式：前端开局向导 AI 席位旁上传 zip（只需自己的源码），编译通过后自动选中，直接开局或 AI 走到底。

### 2. 输入输出协议

棋谱分两种：传给 AI 的是精简快照（只有当前状态，字段见 `backend/app/ai_cpp_example/README.md`）；
`GET /api/games/{id}/export` 返回完整棋谱（带历史，仅回放/复盘用）。前端导出的回放文件为
`quoridor-replay/1` 格式（头部静态＋每步增量事件＋变化字段差分），体积约为全快照的 1%。

**阶段零：出题与选边。** 出题输入 `{"phase":"goals","n":..,"m":..,"deads":..,"sands":..}`（预览地形，与开局一致），
输出 `{"goal_A":[...],"goal_B":[...]}`（各 m//2 列）；选边输入地图与 A/B，
输出 `{"side":"first"}` 或 `{"side":"second"}`。向导里 AI 出题/选边走
`POST /api/ai/goals`、`POST /api/ai/side`；`POST /api/ai/match` 用 `chooser` 指定出题方。

**阶段一：赛前选技能卡。** 输入 `{"phase":"select","skill_k":k,"n":..,"m":..,"deads":..,"sands":..,"goal_A":..,"goal_B":..}`，
输出 `{"skills":[...]}`（恰好 k 张，可重复；技能 id 见 `GET /api/skills`）。

**阶段二：单事件决策。** 输入含 `protocol_version=2`、事件预算、剩余行动次数、技能使用锁、强制移动和双方公开技能效果（完整字段见示例 README）。

普通输出 `{"action":{"type":"move","to":[1,4]}}`；非流沙技能可与该动作一起提交，例如 `{"skill":"double_move","action":{"type":"move","to":[1,4]}}`。连续行动的第二步由后端携带真实新状态再次请求，无需提前模拟。

流沙单独输出 `{"skill":"make_sand","to":[4,4]}`，后端放置后再请求当前方行动。其他技能不能单独作为 AI 事件提交。每次成功提交恰好计一个事件；非法事件整体拒绝。旧 `actions` 数组协议不再接受，已上传 AI 需修改后重新上传。

`events` 记录已完成事件，`event_limit` 默认 800；`remaining_events=event_limit-events`。移动、放墙、放置流沙各计一次，普通技能加动作仍只计一次。到达上限立即判平，最后一个事件到达目标则先判胜。创建对局可指定 `event_limit`；对战接口现有 `max_plies` 参数和 `plies` 结果统一按事件数解释。

### 3. 打包规范（上传 zip）

- 只收 `.cpp/.cc/.c/.h/.hpp`；最多 64 个文件、解压后 ≤8MB；须至少包含一个源文件（多文件一起编译链接，拍平为单目录，头文件用同目录 `#include`；`ai_common.hpp`/`json.hpp` 无需打包，后端自动提供）。
- 编译出的二进制即 AI 本体：固定从 stdin/stdout 按协议交互，无参数、无网络。
- Docker 不再设置 `--cpus` 核数配额（宿主机或 Docker 虚拟机的总资源配置仍生效）。
- 单步默认超时 5 秒（向导可配 1\~30 秒）、内存默认 256MiB（向导可配 64\~2048MiB）；超时/崩溃/无输出判负。
- 开局向导的 AI 下拉 = 默认列表：内置贪心/随机（容器）+ 已上传；AI 席位旁可直接上传 zip，编译通过后自动选中。

### 4. 上传与对战（后端接口）

```bash
# 上传源码 zip 并在容器内编译 → 返回 aid
curl -F "file=@my_ai.zip" http://127.0.0.1:8000/api/ai/upload
# 查看已上传 AI 与编译状态
curl http://127.0.0.1:8000/api/ai/list
# 已上传 AI 在指定对局走一步（人机对战、演示用）
curl -X POST http://127.0.0.1:8000/api/games/{gid}/ai-external-move \
  -H 'Content-Type: application/json' -d '{"aid":"<aid>"}'
# 自动对战（双方各为 "random" 或 aid，直至终局/犯规/超步数）
curl -X POST http://127.0.0.1:8000/api/ai/match \
  -H 'Content-Type: application/json' -d '{"white":"<aid>","black":"random","seed":7}'
# 批量对战（后台并行 N 局，seed=base+i，每局独立出题/选边/选牌；立即返回 job_id 轮询）
# 前端顶部“批量对战”进独立面板：配对局数/并行数，实时看进度与进行中步数，完赛看胜率统计、
# 逐局查看棋谱（预览内可返回/切换上下局）、打包下载全部棋谱 zip
curl -X POST http://127.0.0.1:8000/api/ai/batch \
  -H 'Content-Type: application/json' -d '{"white":"<aid>","black":"<aid>","games":20,"max_parallel":4}'
curl http://127.0.0.1:8000/api/ai/batch/{job_id}          # 进度：完成数、进行中各局步数、已完赛结果
curl http://127.0.0.1:8000/api/ai/batch/{job_id}/games/0  # 单局棋谱（按决策日志重放，前端可直接载入回放）
curl -OJ http://127.0.0.1:8000/api/ai/batch/{job_id}/download  # 打包下载全部棋谱 zip
```

犯规（非法决策）、超时者判负；超出步数上限判平局（`winner=-1`）。

### 5. 规则要点（AI 需注意）

1. 死点不可进入；流沙进入后**对方连续行动两次**（首末行天然无死点/流沙），正常赶路应避开流沙。
2. 墙为长 2 的直墙（横/竖）；改造现打现放 1+1 的 L 墙（不放即作废）；A、B 为相互独立的获胜列集（可相交）。
3. 墙不能复用已有边；放墙后双方必须有路通往各自目标，围死自己或对方均非法。
4. 到达己方获胜点立即获胜；跳子规则：相邻对方棋子时直线跳过，直线落点被挡（出界/死点/墙）则改走其两侧斜格，对方所在格不可停留。
5. 技能：行动前可打出一张（不占轮次），连续行动序列中最多一张；“连续行动”的两步都必须是走子，分别请求与提交，
   对方踩流沙送的两次则可放墙；踩中流沙则剩余步数被覆盖；
   “流沙陷阱”禁死点/已有流沙/棋子格/获胜点；使用技能双方均会得知。

### 6. 基线强度

- 随机示例（`ai_random.cpp`，`builtin-random`）：正规协议+本地合法性复算的随机策略，最弱对手；
  接口与对战里的 `"random"` 为保留别名，均指向它。
- C++ 贪心示例（`ai_example.cpp`）：BFS 最短路推进、给对方挡路的墙、四技能启发式使用；
  实测 9×9 对容器随机六战全胜（先/后手各三局，约 20 步终结），已进默认列表（`builtin-greedy`）。
